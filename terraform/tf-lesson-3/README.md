# Modular Architecture & Terragrunt — Cheat Sheet (Lesson 3)

## Project Structure

```tree
tf-project/
├── root.hcl                  # Root Terragrunt config — provider/backend generation
├── envs/
│   ├── dev/
│   │   └── terragrunt.hcl    # env-specific inputs only
│   └── prod/
│       └── terragrunt.hcl
└── modules/
    └── app-storage/           # Reusable module — NO provider block here
        ├── main.tf
        ├── variables.tf
        └── outputs.tf
```

> ⚠️ Root config file naming: newer Terragrunt versions warn against naming the
> root file `terragrunt.hcl` (ambiguous with env-level files). Use `root.hcl` instead.

## Module Basics

- A **module** is a reusable unit of `resource`/`variable`/`output` blocks — like a function.
- **Never put a `provider {}` block inside a module.** Modules should stay provider-agnostic;
  the provider config belongs in the root/env config only. Two `provider "aws" {}` blocks in
  the same working directory → `Duplicate provider configuration` error.
- Reference a module's outputs from the calling config: `module.<name>.<output>`

```hcl
# Calling a module directly (no Terragrunt)
module "storage" {
  source      = "../../modules/app-storage"
  environment = "dev"
  bucket_name = "myapp"
}

output "dev_bucket_arn" {
  value = module.storage.bucket_arn
}
```

## Terragrunt Core Files

**`root.hcl`** (project root) — generates the provider config into every module run:

```hcl
generate "provider" {
  path      = "provider.tf"
  if_exists = "overwrite"
  contents  = <<EOF
provider "aws" {
  region                      = "us-east-1"
  access_key                  = "test"
  secret_key                  = "test"
  skip_credentials_validation = true
  skip_metadata_api_check     = true
  skip_requesting_account_id  = true
  s3_use_path_style           = true

  endpoints {
    s3  = "http://localhost:4566"
    iam = "http://localhost:4566"
    sqs = "http://localhost:4566"
    sts = "http://localhost:4566"
  }
}
EOF
}
```

**`envs/dev/terragrunt.hcl`** — minimal, environment-specific inputs only:

```hcl
include "root" {
  path = find_in_parent_folders("root.hcl")   # must match root file's actual name
}

terraform {
  source = "../../modules/app-storage"
}

inputs = {
  environment = "dev"
  bucket_name = "myapp"
}
```

## CLI Commands (Modern — post CLI Redesign)

Terragrunt deprecated the standalone `*-all` commands. All multi-module operations now go
through the unified `run` command with the `--all` flag.

| Old (deprecated) | New (current) |
| --- | --- |
| `terragrunt plan-all` | `terragrunt run --all plan` |
| `terragrunt apply-all` | `terragrunt run --all apply` |
| `terragrunt destroy-all` | `terragrunt run --all destroy` |
| `terragrunt run-all <cmd>` | `terragrunt run --all <cmd>` |
| `TERRAGRUNT_*` env vars | `TG_*` env vars |
| `--terragrunt-xxx` flags | `--xxx` (prefix dropped) |

### Single-module commands (run from `envs/dev/`, etc.)

```bash
terragrunt init
terragrunt plan
terragrunt apply -auto-approve
terragrunt destroy -auto-approve
```

### Multi-module commands (run from `envs/`, the parent of all env folders)

```bash
terragrunt run --all plan
terragrunt run --all apply
terragrunt run --all destroy

# Non-interactive (CI-safe, auto-approves each apply)
terragrunt run --all --non-interactive -- apply
```

## Common Errors & Fixes

| Error | Cause | Fix |
| --- | --- | --- |
| `ParentFileNotFoundError: Could not find a terragrunt.hcl in any of the parent folders` | Root config file is not actually in a parent directory of the env folder | Move root file to the true project root; confirm the path with `find_in_parent_folders()` |
| `Duplicate provider configuration` | A `provider "aws" {}` block exists both in the module **and** is generated by Terragrunt | Remove any `provider {}` block from module files — only `root.hcl` should define it |
| `unknown command: "run-all"` | Using a Terragrunt version with the CLI redesign | Use `terragrunt run --all <command>` instead |
| `You attempted to run terragrunt in a folder that does not contain a terragrunt.hcl file` | Ran `terragrunt run --all` from a directory with no terragrunt config (e.g. the project root, if it only has `root.hcl`) | Run from a directory whose children contain `terragrunt.hcl` files (typically `envs/`) |

## Cleaning Stale Cache

Terragrunt copies module code into `.terragrunt-cache/` before running Terraform.
If you edit a module and still see old errors, clear the cache first:

```bash
find . -type d -name ".terragrunt-cache" -exec rm -rf {} +
```
